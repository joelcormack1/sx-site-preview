# 626 Website Prototype — Consolidated Review Report

52 verified findings from six review beats, deduplicated to 37 entries (the SXGrid.attach leak was reported by four beats, the `.fd.seen` override by three, the dead hoverlaw.js engine by two; each is one entry below).

## Bugs

### [HIGH] Firefox mouse-wheel scrolling is effectively frozen — `smoothscroll.js:40`
The wheel handler preventDefaults the native scroll and adds raw `e.deltaY` to the target, but never checks `e.deltaMode`. Firefox with a physical mouse sends line-mode deltas (deltaMode=1, deltaY ≈ 3), so each notch advances the page ~3px instead of ~120px while the native scroll is suppressed. Trackpads are fine; every Firefox mouse user gets a page that barely moves. Stock Lenis, which this file claims to reproduce, normalizes this.
**Fix:** Multiply line-mode deltas before adding: `const dy = e.deltaMode === 1 ? e.deltaY * 40 : e.deltaMode === 2 ? e.deltaY * innerHeight : e.deltaY;`

### [HIGH] Footer-law page height ratchets up and never shrinks — `footerlaw.js:20`
`apply()` computes `wantH = max(pageH, vh)` where `pageH` is read back from the page's computed height, which already includes footerlaw's own previous stretch. The natural content height is never remembered, so the page can only grow. Because view.html makes the iframe viewport a function of window width, a narrow-then-wide resize leaves the page permanently two viewports tall with a giant blank band above the footer — a direct footer-law violation on every page that doesn't rewrite its own height on resize (case-studies, case-study, creatives, about, experiential; index/director/careers/contact/services self-heal).
**Fix:** Capture the natural content height once at `arm()` and use `max(naturalH, vh)` instead of `max(currentH, vh)`.

### [HIGH] Stray white chevron at the top-left of the director hero; scroll affordance missing — `director.html:484`
`#chevDown` has no class and no CSS rule gives it `position:absolute`, so it lays out statically as the hero's only in-flow child, at (0,0) — a stray white chevron under the transparent header on every load. `fitHero`'s `style.top = HERO_H - 45` (line 801) is a no-op on a static element, so the designed scroll-down affordance is absent from the hero bottom (its click handler is wired to an element sitting at y=0).
**Fix:** Add `#chevDown { position: absolute; left: ...; cursor: pointer; }` mirroring the old `.h-chev-unused` geometry.

### [HIGH] About header goes invisible for the entire page below the reel — `about.html:521`
The `zoomed` condition (`scrollY >= AB_REEL_PIN - 10 && hp >= 0.999`) has no release bound: `hp` clamps at 1 for all scrollY ≥ 853, so `.hdr.dark` stays on forever once you pass the reel. The sticky header becomes transparent with white text and a white-inverted lettermark over the white core-values, team, and pre-footer sections — the whole header chrome is invisible and page content scrolls through the band for thousands of pixels. The code comment says dark chrome should apply only "while the reel holds full screen."
**Fix:** Also require `scrollY <= 853 + REEL_GROW + REEL_LOCK` (the reel unpin point) in the `zoomed` condition.

### [HIGH] Missing merged `.fd.seen` rules break three designed transitions (the recurring "8/19 snap bug") — `about.html:149`, `services.html:188`, `index.html:230`
Elements that carry both a component transition and `fd seen` classes lose their designed timing because `.fd.seen` (specificity 0,2,0) overrides the component rule (0,1,0). Worst case is about.html: `#cvCopy`'s 0.25s crossfade is replaced by a 0.9s + 0.15s-delayed fade, so `setVal`'s 180ms text swap happens while the copy is still ~80% opaque — every one of the six core-values scroll steps shows a hard text swap instead of a crossfade (high). Same mechanism, cosmetic-only: services testimonial cards animate at 0.9s instead of 0.5s (`services.html:188/552`), and index press cards page at 0.9s instead of 0.35s (`index.html:230/750`). Four grid pages already patched exactly this with merged rules.
**Fix:** Add merged `.cv-copy.fd.seen`, `.tst-card.fd.seen`, and `.press.fd.seen` rules restoring each component's opacity timing.

### [MEDIUM] Creatives header is the only non-sticky header — MENU scrolls off-screen — `creatives.html:56`
`.hdr` is `position: absolute` here while all nine other pages use `position: sticky; top: 0`. That was harmless when the page was one viewport tall, but the 8/21 footer-law sizing script now makes the page scroll, so the header — including the MENU button, the site's only navigation — scrolls off the top and is unreachable for the rest of the page.
**Fix:** Change `.hdr` to `position: sticky; top: 0` matching every other page (keep its z-index above `#reels`).

### [MEDIUM] Go-home logo morph renders white-on-white from dark-header pages — `logomorph.js:176`
The click-home showpiece builds a white wash at z-40 and animates the letters to full SIX26 above it — but on case-study.html and director.html the header is `.hdr.dark`: transparent background with `#lettermark` inverted to white. During the 600ms exit the page fades to solid white while the letters stay inverted white, so the entire grow morph is invisible; the user sees the page blank out and home simply appear.
**Fix:** In the click handler, remove the header's `dark` class and clear any invert filter on `#lettermark` before starting the wash.

### [MEDIUM] Smoothscroll has no programmatic hook: its tick cancels tab-click navigation and keeps scrolling under the open menu — `smoothscroll.js:23-37`, `services.html:497`, `menu.js:217`
Two symptoms, one root cause. (1) Stepper tab clicks use native `scrollTo({behavior:'smooth'})`, but smoothscroll's rAF tick keeps issuing instant `scrollTo` calls for up to ~1s after the last wheel event, and any scroll on the same box aborts an in-flight smooth scroll — so clicking a tab while the damper is still settling (the normal interaction) kills the navigation and the clicked step is never reached (also `case-study.html:289`). (2) Opening the menu sets `SX_SCROLL_LOCKED`, but that flag is only checked for new wheel events; an already-animating glide keeps calling `scrollTo` every frame, so the page visibly drifts behind the dark scrim, and on the homepage the drift makes the menu's open-time header snapshots stale at close.
**Fix:** Expose `window.SXScroll.stop()` and `SXScroll.to(target)` in smoothscroll.js; call `stop()` in menu `open()` and use `to()` for all programmatic scrolls.

### [MEDIUM] `SXGrid.attach()` has no teardown: listener/DOM leak on every relayout, plus a stale-ghost hazard — `gridhover.js:156`, `case-studies.html:367`, `director.html:945`
Every `attach()` registers a fresh window scroll + mousemove listener and never removes them. case-studies re-attaches on every filter-tab and density click; director on every category switch. After k clicks the page carries 2(k+1) permanent window listeners, each closure retaining the full previous tiles array (detached anchors, captions, decoded images) — unbounded growth, and every scroll fans out through every dead closure. User-visible hazard: a stale instance whose tile was removed mid-hover never gets `mouseleave`, so the next >40px scroll fires the dead instance's `leave()`, which strips the shared ghost class off the live grid mid-hover. Bonus on director: the glide check is keyed on category name, so Featured↔Commercial (identical 6-tile lists for Evan) hard-rebuilds with a pop instead of the mandated 0.7s glide.
**Fix:** Have `attach()` return a `detach()` handle (remove both listeners, drop tiles) and call it before re-attaching; key director's glide check on list content, not category name.

### [MEDIUM] Creatives roster: hidden reel videos pile up playing on row-to-row hovers — `creatives.html:242`
`mouseenter` clears the leave timer and plays the new slot's video but never pauses the previous one; the only pause lives in `clear()`, which runs on a 90ms timer that a direct move to the next row cancels. Sweeping the cursor down the 15-name roster leaves up to fifteen muted 1080p Vimeo streams downloading and decoding simultaneously at opacity 0 — real CPU/bandwidth/battery cost competing with the visible reel's buffering.
**Fix:** In the enter handler, pause every slot video except `slots[i]`.

### [MEDIUM] Creatives reels are signed Vimeo URLs that WILL expire, and failure is silent — `creatives.html:191`
All 15 roster videos carry `signature=` tokens pulled from the live site on 8/19; the file's own header comment acknowledges they expire. When they start 403ing, `v.play().catch(() => {})` swallows every error, so hovers silently show only the poster still and nobody notices the reels are dead. Posters also hotlink `api.sixtwentysix.co`, so the page depends on live WP infra and breaks offline.
**Fix:** Pull the renditions once into `assets/reels/` while the signatures are valid and reference locally; at minimum add an `error` listener that badges dead rows.

### [MEDIUM] Director ledger preview shows the previous row's image for 16 of 20 rows — `director.html:1004`
`preview()` updates title and director on every row hover but only swaps the image `if (row.dataset.shot)` — and only 4 rows carry `data-shot`. Hovering any of the other 16 shows the new brand's title over the previous brand's still, exactly the title/image disagreement the adjacent comment says this code was written to prevent. Six of those rows have matching stills already on disk in `assets/live/` (turo, dunkin-pump, palms, pacifico, creditkarma, squarespace). The static `.l-serv` services line (line 584) also always describes PURA regardless of row.
**Fix:** Add `data-shot` to the six rows with stills, fade `l-shot` to the `#d9d9d9` placeholder for shotless rows, and drive `.l-serv` per row.

### [MEDIUM] Team marquee whooshes backward a full lap every ~93s, and shows blank rail at the slide extremes — `about.html:476` and `:462`
Two defects in one marquee. (1) The seamless-loop wrap (`drift % PERIOD`) requires an instant snap, but `#tmTrack` carries `transition: transform 0.6s`, so when drift wraps from 2230.5 back to ~0 the transitioned transform animates a 2230px jump — the rail visibly rewinds a full lap every PERIOD/24 ≈ 93 seconds. (2) The two-copy buffer doesn't cover the pos×drift range: Prev×2 right after load shows ~860px of blank rail on the left (verified numerically), and pos=2 near drift max shows ~369px blank on the right before each wrap.
**Fix:** Apply drift on a separate un-transitioned wrapper (keep the transition for chevron paging only), and add a third roster copy at −PERIOD (or wrap-normalize pos into drift).

### [MEDIUM] Experiential "how we make it happen" rows render 146px below their authored tops — `experiential.html:253`
`#hproc` carries class `fd`, whose pre-reveal `translateY(28px)` makes it the containing block for its absolutely positioned `.hp-row` children; since #hproc is an in-flow block after the 118px header, `top:2666` resolves from y=146. The 8/21 comment noticed the "drifted 146px" and papered over it by measuring, but the pinned block's internal geometry is still distorted (heading-to-rows gap renders 374px vs the authored 256px), and because `reveal=1` neutralizes `.fd` transforms, captures show the correct design while the live page shows the distorted one — invisible in review.
**Fix:** Give `#hproc` `position:absolute; left:0; top:0` (or move `fd` onto the rows) so the authored coordinates and the measured lock agree.

### [MEDIUM] Case-study footer paints over the film hero in capture mode — `case-study.html:246`
The footer ships at inline `top:0px` and relies entirely on footerlaw.js to seat it at 2291 — but footerlaw returns immediately on `reveal=1`, so in the documented headless-capture mode the black 349px footer sits over the top of the hero and header band. It also risks a brief footer-over-hero flash on normal loads before DOMContentLoaded. (creatives.html:161 and director.html:718 also rest at top:0 and share the flash risk.)
**Fix:** Hardcode the real design top inline (2291 here) on all three pages and let footerlaw only correct deltas.

### [MEDIUM] view.html never syncs `?p=` to the current page — any shell reload dumps the user on the homepage — `view.html:39`
The deep link is read once at shell load and never updated as the user navigates inside the iframe. The bfcache guard calls `location.reload()` on every persisted pageshow, so returning via back/forward in Safari reloads the shell with the stale (or absent) `?p` and lands on index.html, discarding wherever the user was. F5, crash restore, and sharing the address-bar URL all hit the same hole — in the shell whose whole job is being the shareable review surface.
**Fix:** In the iframe load handler, `history.replaceState(null, '', '?p=' + currentPage)` (the stale-tab killer at lines 52-54 already shows how to read the current page).

### [LOW] Menu close handoff pops: stale header state and a hard-appearing (R) — `menu.js:233-240`
Two related handoff glitches at close. The (R) law is a delayed 0.35s fade-in after lock, but `closeTimer` swaps to the real header at exactly 500ms — the instant the tween reaches q=1 — so the menu's R is still transparent while the page header's R sits at opacity 1: it pops on instead of fading. And if the menu was opened during the homepage's ~1.5s assembly, close tweens to the stale open-time `startQ` while `hdrTick` kept settling the hidden header, producing a visible snap at the swap.
**Fix:** Extend `closeTimer` past 500+120+350ms (or re-run the R fade at handoff), and re-read live `SX_MORPH_Q` / `.hdr-bg` height at close time instead of the open-time snapshots.

### [LOW] Enter in an empty menu search navigates to Creatives — `menu.js:252`
The Enter handler follows the first non-dimmed link, and with an empty query nothing is dimmed — so a stray Enter in the autofocused search field (focused 250ms after open) ships the user to creatives.html, or reloads the current page since `.here` links aren't excluded.
**Fix:** `if (!search.value.trim()) return;` and skip `.here` links as Enter targets.

### [LOW] Homepage sheet-drift anchor is 28px off and stale after resize; hero hides before the sheet covers it — `index.html:592` and `:527`
`nat` is cached from the statement's rect while it is still un-revealed (includes the pre-reveal `translateY(28px)`), so the whole drift band is permanently 28px low, and it is never recomputed on resize even though `fitHero` moves the statement. Separately, `updateHero` hides the fixed reel at a precomputed scroll threshold while the sheet can still be ~17px shy of its seat in viewports shorter than ~902 design px — a one-frame white strip flashes between header and sheet.
**Fix:** Compute `nat` from layout coordinates (and null it in the resize handler); hide the hero from `sheet.getBoundingClientRect().top <= 118` instead of a scroll constant.

### [LOW] Scroll-exit lock leaves the tile under the cursor permanently dead — `gridhover.js:157`
After a >40px scroll force-exits a hover, `lock` is only cleared by mousemove — but the tile the cursor is already resting inside will never refire `mouseenter` (the browser's post-scroll boundary events arrive while lock is still true and are swallowed). That tile stays hover-dead until the user fully exits and re-enters it, contradicting the stated intent that movement alone re-arms hover.
**Fix:** In the mousemove handler, when lock was set, clear it and re-run `enter()` on the element under the cursor (`document.elementFromPoint`).

### [LOW] Director: quick re-enter within 720ms strips `gh-big` mid-hover — `director.html:950`
`onLeave` schedules `classList.remove('gh-big')` at 720ms without storing the timer, and `onEnter` never cancels it — so a quick out-and-back on the same tile has the stale timer remove z-index:20 and swap the transition list in the middle of the new hover, risking dimmed caps painting over the enlarged tile and an interrupted 0.7s glide.
**Fix:** Store the timer on the tile and `clearTimeout` it in `onEnter`.

### [LOW] Top ~10px of "Back to work" is shadowed by the lettermark hit area — `case-study.html:219`
The header's `#lettermark` anchor is 161px tall inside the z-50 sticky header, extending 43px below the 118px band; `.cs-back` sits at y151-175 in a lower stacking context, so clicks in the y151-161 band navigate to index.html (triggering the home morph) instead of case-studies.html.
**Fix:** Move the link below y161, or shrink the lettermark's hit box (the morph drawing doesn't need the full 161px).

## Improvements

### [MEDIUM] The scroll-reveal IntersectionObserver block is copy-pasted across every page — `services.html:346`, `case-studies.html:278`, `case-study.html:293`, et al.
The full reveal engine — 0.15 ratio rule, zero-size-wrapper exemption ("8/19 bug"), one-shot unobserve ("8/21 bug") — is duplicated verbatim with identical dated comments proving it has already needed two behavioral fixes hand-propagated to every page. The next fix will drift; this is exactly the failure mode gridhover.js was extracted to prevent for hover.
**Fix:** Extract to a shared `reveal.js` (observe `.fd`, export the observer for late-created nodes) loaded like footerlaw.js.

### [MEDIUM] In-frame navigation bypasses the cache-buster the shell exists for — `view.html:37`
The `?r=Date.now()` stamp applies only to the first page loaded into the iframe; every subsequent in-page link is a bare href, and the pages carry no Cache-Control meta. Under header-less dev serving, Chrome's heuristic freshness can serve days-old copies of every page after the first — the exact stale-build confusion the shell's own comments document fighting twice.
**Fix:** Rewrite same-origin nav clicks in shared JS to append the shell's stamp, or serve with `Cache-Control: no-store` and drop the stamp.

### [MEDIUM] Footer typography has drifted between pages — director is the stale copy — `director.html:107` vs `creatives.html:113`
The hand-copied footer block renders in two typefaces: creatives (and index) use Azeret Mono columns per the 2026-08-18 Full Site re-sync (which index's header comment says supersedes the earlier all-Helvetica rule), while director's `.foot-col` has no font-family and inherits Helvetica with `line-height: normal`. Same footer, two looks.
**Fix:** Bring director's footer up to the Azeret spec, and move the footer markup/CSS into one shared include (footerlaw.js already touches every footer) so it can't drift again.

### [LOW] Dead second hover engine (hoverlaw.js) still shipped on four pages — `hoverlaw.js:27`
`BRACKETS = false` makes the file a guaranteed no-op, yet it's still loaded by index.html:800, director.html:1016, case-studies.html:399, and experiential.html:432. Its selector list targets the exact tiles gridhover owns, so flipping BRACKETS back on would attach a second engine (MutationObserver + injected children + its own handlers) to engine-managed tiles — a violation of the one-hover-engine law waiting to happen. takeover.js is likewise unused by any live page.
**Fix:** Remove the four script tags and archive both files (fold the video-preview idea into gridhover.js if ever wanted).

### [LOW] All 15 creatives rows link to the same director.html; the `slug` field is never read — `creatives.html:237`
Clicking Gianluigi Carella or any other name opens Evan Bourque's page with no placeholder indication, and reviewers will keep reading it as a routing bug. The ROSTER entries (the declared WordPress seam) already carry unused `slug` fields.
**Fix:** Wire `row.href = 'director.html?d=' + d.slug` now, with director.html defaulting to evan-bourque when the param is absent.

### [LOW] PURA and SQUARESPACE ship on the homepage but are missing from the case-studies ledger — `case-studies.html:300`
Both are numbered works on index (004 PURA, 009 SQUARESPACE) with images on disk, but neither appears under any case-studies filter — the two content arrays (the WordPress seam) have already drifted, unless the omission is editorial.
**Fix:** Add the two WORKS entries with cats, or note the deliberate exclusion in the WORKS comment.

### [LOW] Director index-mode height is a magic 1108 that the hardcoded ledger already overflows by 219px — `director.html:958`
The 20 ledger rows end at grid-relative 1327 against the 1108 budget; the overflow survives only by eating the +300 rhythm padding, leaving 81px above the footer. Every future row is +54px, so two more rows silently run under the black footer with nothing signaling why. `#ledger`'s CSS `height:1258` is similarly detached from content.
**Fix:** Derive the index-mode end from the rows (`183 + 64 + rowCount*54`) or from `ledger.getBoundingClientRect()`.

### [LOW] Uncancelled copy-fade timeouts flash stale text on fast scrubs — `about.html:342`, `experiential.html:366`
`setVal`/`show` schedule the text swap on a setTimeout without keeping a handle; the damped smoothscroll can cross multiple 200px steps within one fade window, stacking timeouts so an intermediate value's copy flashes at full opacity just before the final one lands. Same pattern in both pages — a candidate for one shared stepper helper.
**Fix:** Store the timer and `clearTimeout` at the top of each call.

### [LOW] Services stepper runs a permanent per-frame rAF poll duplicating its scroll listener — `services.html:490`
`stepFromScroll` is bound to the scroll event AND driven by a self-rescheduling rAF loop checking `scrollY` every frame forever, on a page already running the smoothscroll rAF. The equivalent steppers on about and experiential use the scroll listener alone.
**Fix:** Drop the tick loop (or gate it to stop when idle).

### [LOW] About reel lock is measured once at load and never on resize — `about.html:363`
`REEL_H`, the baked `REEL_GROW` shifts, and the centering offset are all captured at load; enlarging the window afterward leaves the pinned "full screen" reel shorter than the viewport with a white band beneath it — while the core-values box on the same page does re-center on resize, so the page is half resize-aware.
**Fix:** Add a resize handler that re-derives `rs.style.top` and stretches the reel/hero height when `innerHeight` exceeds `REEL_H`.

### [LOW] gridhover gap math assumes the left neighbor shares the hovered tile's width — `gridhover.js:85`
`gapL` subtracts the hovered tile's own width where the left column's width belongs (line 58 already computes the correct per-column scan for the unused global gap). Latent today (uniform columns, ~1px error) but it becomes an overlap generator — a violation of the no-overlap law — the moment mixed tile widths arrive through the WordPress content seam.
**Fix:** Reuse the per-column width scan: `gapL = xs[colIdx] - xs[colIdx-1] - maxWidthOfColumn(colIdx-1)`.

### [LOW] Menu polish: reopen-during-close snaps, and open on dark headers flashes a white band — `menu.js:200`, `:205`
Reopening while the 500ms close is mid-flight unconditionally restages with transitions off, so the letters and sheet visibly jump to fully-closed before growing again (tweenQ already supports starting from the live q). And on dark transparent headers (case-study, director) the first frame of open hard-cuts an opaque white 118px bar onto the dark hero before the grow, breaking the header-grows-into-menu continuity.
**Fix:** Skip the restage when the overlay is still `shown`; fade the sheet background in over the first ~150ms when the header is dark.
